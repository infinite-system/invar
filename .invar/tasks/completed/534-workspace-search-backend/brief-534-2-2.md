# Brief 534-2 — ripgrep does not exist on this machine

## In plain words

Your tests passed in your sandbox because it ships ripgrep. The target
machine has no rg anywhere, so every backend search reports failed and
six gate tests are red. The app must search without assuming rg is
installed. Resolve the binary through a seam with an honest fallback.

## End state (mechanically checkable)

A report newer than this brief's stamp; `bun test
src/modules/search/WorkspaceSearchBackend.test.ts` green ON THIS MACHINE
(where `which rg` returns nothing); the failure log's
`Executable not found in $PATH: "rg"` class impossible by construction.

## Evidence

- Gate log /tmp/merge-gate-failures.2c4ce89b2463d45f.3097918/: six
  "real ripgrep integration" tests, state "failed"; the stderr carries
  `error: Executable not found in $PATH: "rg"`.
- Conductor: `which rg` empty; /usr/bin/rg, /usr/local/bin/rg,
  ~/.cargo/bin/rg all absent.

## Ranked options (pick with reasons; the seam is required either way)

1. Vendor `@vscode/ripgrep` as a dependency (prebuilt binary, ~5MB) and
   resolve: PATH rg first (newer wins), vendored second. Tests then run
   everywhere. Check bun install postinstall behavior works offline/CI.
2. Resolution seam with an honest "search unavailable: ripgrep not
   found" outcome surfaced as a distinct backend state (NOT "failed" —
   the user must see why), plus a pure-JS fallback walker for small
   workspaces if cheap. Tests mock the resolver's absent arm.
3. Require rg as documented dependency and gate-skip integration tests
   when absent — LAST resort; a skip is not a pass, argue it only if 1
   and 2 are genuinely wrong per the design.

Whatever you pick: binary resolution goes through ONE seam (External
tools share one launch policy), the absent-arm is a TESTED state, and
the missing-tool message names the remedy.
